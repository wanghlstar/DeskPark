# 五子棋、跑得快、黑白棋接入计划

**目标：** 三款游戏接入现有大厅、单人电脑、联机房间与可选大模型接管，保持飞牛和 Android 共用构建。

**方案：** 规则实现 `GameDefinition`，状态为可序列化纯数据，电脑只读取座位视图。棋类复用双人布局，跑得快复用扑克牌、选牌和结算组件；不增加服务进程或运行时依赖。

## 规则与来源

- 五子棋：15×15 自由规则，黑先、连成至少五子获胜，无禁手；入门/普通/困难电脑，人机局可悔棋。移植 [retro-arcade](https://github.com/Minjia-Hu/retro-arcade) 的纯 TypeScript 棋形评估和搜索，保留 MIT 声明，限制搜索节点以适应手机与服务端。
- 跑得快：参考 [paodekuai_ai](https://github.com/esrrhs/paodekuai_ai) 的三人 48 张规则移植到 TypeScript；每人 16 张，保留三张 A、一张 2，无王。固定黑桃 3 先手且首手包含它；有大必压，领出单张时下家报单必须出最大单张。支持三带任意两张、两连对、顺子、三顺、飞机及炸弹，不含四带二；剩牌计负分，16 张未出双倍，零和结算。电脑使用本地策略，不引入原项目的多语言服务或模型运行库。
- 黑白棋：标准 8×8，黑先、八方向夹吃、无合法位置自动让行，双方均不能走则按棋子数结算；三档电脑与人机悔棋。规则独立实现，参考 [react-reversi](https://github.com/jhewlett/react-reversi) 的玩法边界。

## 执行与验收

1. 五子棋：先写胜负、非法落子、人机悔棋、战术防守及完整模拟测试并观察失败，再实现规则与搜索、注册和棋盘界面。
2. 跑得快：先写牌型、必压、首出、报单、计分、暗牌隐藏和牌数守恒测试并观察失败，再实现规则/候选/电脑/牌桌。
3. 黑白棋：先写八向翻转、让行、终局、悔棋和完整模拟测试并观察失败，再实现规则/电脑，复用棋盘展示。
4. 三款加入候选合法性和畸形动作测试；浏览器验证单人、两个设备联机、手机横竖屏、结算及 AI 接管。
5. `npm run check`、格式检查、生产构建、FPK 服务测试与归档检查通过后，更新版本、来源声明和发布说明，通过现有 Actions 发布新的 Alpha 并核验附件。
