# 飞牛 fnOS 应用包

DeskPark 提供原生 FPK，安装包包含完整网页和联机服务器，依赖飞牛应用中心的 **Node.js 22**（`nodejs_v22`）。服务以专用应用用户运行，同一包可用于 x86 和 ARM 设备。

## 下载与安装

1. 打开仓库的 [fnOS FPK 工作流](https://github.com/wanghlstar/DeskPark/actions/workflows/fnos.yml)，选择一次成功的构建，在 Artifacts 下载 `deskpark-fnos`。
2. 解压后得到 `deskpark-0.3.6.fpk` 和对应的 `.sha256`。构建使用项目版本号，后续版本的文件名会随之更新。
3. 在飞牛应用中心使用手动安装，选择 `.fpk`，按提示安装 Node.js 22 依赖。
4. 在「设置访问端口」步骤填写服务端口，默认 **8787**，可选 **1024–65535** 之间未被占用的端口。在「服务器默认 AI（可选）」步骤填写协议、地址、Key 和模型，无需 AI 时留空。完成安装并启动应用。
5. 点击「闲亭 DeskPark」桌面图标，或用浏览器访问 `http://飞牛IP:填写的端口`。例如填写 `18878`，则访问 `http://飞牛IP:18878`。其他设备访问同一地址即可创建、加入联机房间。

FPK 使用官方 fnpack 的 `--nosign` 生成，供手动安装测试，尚未作为签名应用上架应用中心。请在支持第三方应用手动安装的飞牛版本上测试；本项目尚未完成飞牛实机安装验证。

已发布的测试版本也可直接从 [Releases](https://github.com/wanghlstar/DeskPark/releases) 下载 `.fpk` 和校验文件。`alpha`、`beta` 或 `rc` 等带预发布后缀的标签会标记为 Pre-release。

安装向导会校验端口格式与范围，服务启动时还会检查选定端口是否被占用。端口由飞牛保存为向导配置，服务在重启后继续使用该值；桌面入口会打开同一端口的新浏览器标签页。需要 HTTPS 或外网访问时，可将自己的反向代理指向所选端口，并转发 `/ws` 的 WebSocket 连接，详见 [部署指南](./DEPLOY.md)。

## 配置服务器默认 AI

1. 升级到 `0.3.2` 或更新的 FPK。新安装时可直接在安装向导填写以下配置。
2. 已安装时，打开 **飞牛应用中心 → 闲亭 DeskPark → 设置**，进入「服务器默认 AI（可选）」。
3. 选择 **OpenAI 兼容** 或 **Anthropic**；填写完整接口地址，例如 `http://192.168.2.8:19020/v1`，以及 AI 服务实际提供的 **API Key** 和 **模型 ID**。OpenAI 兼容地址通常带 `/v1`；Anthropic 地址通常不带 `/v1`。
4. 保存后，正在运行的应用会重启，当前联机房间会结束。
5. 打开网页 **设置 → AI 人机 → 服务器默认**，即可看到协议与模型，点击「测试连接」。玩家无需再填写地址、Key 或模型。新设备会优先使用可用的服务器默认；已有自定义配置的设备继续沿用原配置，可手动切换。

所有 AI 字段都可留空。地址和模型均已填写时才启用服务器默认；无需鉴权的接口可不填 Key。清空模型即可关闭默认 AI。只填地址时，兼容 `0.3.1` 的自定义配置转发。

服务器默认的 Key 由飞牛配置保存，只在服务器请求上游时使用，网页只读取可用状态、协议和模型。默认调用固定使用后台地址、模型和 Key，玩家不能在请求中覆盖。

## 玩家使用自己的 AI

在网页 **设置 → AI 人机 → 自定义** 中填写协议、地址、Key 和模型，保存在该设备浏览器中。切换到服务器默认不会删除自己的配置。

**「经服务器转发」只改变请求路径，仍使用玩家自己的配置。** 浏览器直连被跨域拦截时可开启：浏览器 → 同源 DeskPark → 飞牛连接指定接口。它与「服务器默认」是两个独立选项。

自定义转发默认仅允许 HTTPS 公网接口。飞牛配置中的完整地址也作为允许转发的地址，只匹配指定的协议、主机、端口和路径。因此已有 `0.3.1` 的本地地址配置和网页转发设置可以继续使用，玩家仍携带自己的 Key。

关闭「经服务器转发」时，请求由打开网页的 PC / 手机直接发出。即使已组网、`curl` 能调用，浏览器仍要求 AI 服务通过 CORS 预检；同 IP 不同端口也属于跨域。`GET /v1/models` 返回 `401` 说明服务有响应，但此次请求未带有效 Key，不能据此判断带 Key 的模型调用是否成功。

单人对局的规则电脑和大模型接管由浏览器调度；联机房间的规则电脑与托管由服务端调度，当前联机电脑未接入大模型。

## 启停与数据

- 飞牛应用中心的启动、停止和运行状态由 `cmd/main` 管理；启动会检查端口和 `/healthz`。
- 日志写入 `${TRIM_PKGVAR}/deskpark.log`，PID 写入同目录的 `deskpark.pid`。通常可通过 `/var/apps/deskpark/var/` 查找。
- 单人存档、网页设置和自定义 AI 配置保存在各设备浏览器中；服务器默认 AI 保存在飞牛应用配置中。升级 FPK 不会主动清理浏览器数据。
- 联机房间保存在服务进程内存中，停止或升级应用会结束当前联机房间。
- 包内不含运行时安装依赖的步骤；网页和联机服务器随包安装，Node.js 运行时由飞牛管理。

## 构建

仓库的 **fnOS FPK** Actions 工作流支持推送 main、Pull Request 和手动运行，依次执行格式检查、lint、类型检查、规则测试、生产构建、FPK 服务测试和打包。测试产物包含 FPK 与 SHA-256，可在 Artifacts 下载。

推送 `v*` 标签时，**Release** 工作流调用同一套 FPK 和 Android 构建，只有两者都成功才统一发布附件。预发布标签标记为 Pre-release，不设为最新正式版本。发布说明维护在 `docs/RELEASE_NOTES.md`。

本地打包适用于 macOS / Linux。先安装 Node.js 22 和官方 [fnpack 1.3.3](https://developer.fnnas.com/docs/cli/fnpack/)，再运行：

```bash
npm ci
npm run build:fpk
```

如果 fnpack 不在 PATH 中，可以通过 `FNPACK` 指定可执行文件：

```bash
FNPACK=/你的路径/fnpack npm run build:fpk
```

产物位于 `dist/fnos/`。脚本会构建网页和服务端，将运行文件复制到 `dist/fnos/package/`，执行真实服务的生命周期与 WebSocket 测试后再打包。不会在本机安装飞牛应用或修改系统服务。

首次部署到飞牛后，请检查：安装向导可填写端口和可选 AI 配置、应用能启动、桌面入口打开所填端口、两台设备能加入同一房间、停止后所选端口释放，以及重新启动后仍使用同一配置。AI 可从应用中心的「设置」继续修改，保存后在网页重新打开设置即可读取新的默认模型。
